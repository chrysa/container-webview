# DECISIONS — container-webview

> Architectural decisions reconstructed from the working tree on 2026-09-25. These are documentation
> ADRs (observed decisions), not new proposals. The canonical ADR format and the "refutable ADR"
> requirement live in the chrysa standards (`standards/rules/governance.md`, managed block in `CLAUDE.md`).
> No formal per-repo ADR files exist in the tree (UNKNOWN — none found under root or `docs/`).

## ADR-D-001 — Two-surface split: FastAPI backend (`api/`) + React frontend (`code/`)
- Status: OBSERVED / accepted.
- Context: The product is a web UI over the Docker Engine.
- Decision: Separate Python API and TypeScript SPA, each independently built/containerized.
- Evidence: `api/`, `code/`, `docker-compose.yml`.
- Refutation trigger: UNKNOWN (no recorded trigger).

## ADR-D-002 — Thin routers + service layer on the backend
- Status: OBSERVED.
- Decision: HTTP controllers under `routers/` stay thin; business logic lives in `services/`.
- Evidence: parallel `routers/` and `services/` trees; README "HTTP controllers (thin)".

## ADR-D-003 — Stateless JWT auth with local admin fallback and optional LDAP
- Status: OBSERVED.
- Decision: JWT Bearer tokens; local admin (bcrypt hash preferred, plaintext dev-only) with LDAP as
  an optional external identity source.
- Evidence: `security.py`, `services/auth_service.py`, `.env.example`.
- Note: chrysa canon calls for cluster SSO + LDAP directory (`standards/rules/security.md`); the
  local admin fallback is a dev affordance guarded off in production (`config.py`). Multi-user auth
  is on the roadmap (REQ-PROD-012).

## ADR-D-004 — Read-only access to Docker socket and Compose projects
- Status: OBSERVED (security-positive).
- Decision: Mount `/var/run/docker.sock:ro` and the projects directory `:ro`.
- Evidence: `docker-compose.yml`.
- Trade-off: lifecycle actions (start/stop) are issued through the Engine API despite the read-only
  socket mount — the `:ro` limits filesystem writes to the socket file, not Engine command scope.
  See SECURITY.md (Docker socket exposure).

## ADR-D-005 — Multi-stage Dockerfile with explicit dev/test/production stages
- Status: OBSERVED. Aligns with chrysa `dockerfile-multistage` standard.
- Evidence: `api/Dockerfile` (`base`/`dev`/`test`/`production`), compose `target:` selectors.

## ADR-D-006 — Generated context files (ADR D-0012, referenced)
- Status: OBSERVED. `handover.md`, `ai-instructions.md`, `context-map.json`, `llms-full.txt` are
  generated by `scripts/gen_context_files.py`; headers say "do not edit".
- Evidence: file headers; `scripts/gen_context_files.py`.
